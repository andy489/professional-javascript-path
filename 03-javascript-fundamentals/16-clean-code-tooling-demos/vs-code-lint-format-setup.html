ESLint + Prettier in VS Code

JavaScript Fundamentals 2025 — Module 16 companion guide

This guide walks through configuring Visual Studio Code so ESLint reports issues in the editor and Prettier formats your files on save. The steps below assume VS Code and the Node.js 24 LTS baseline used in this course, with ESLint and Prettier already installed as dev dependencies in your project (as the lint-demo project in Clip 4 is).

1. Install the ESLint extension

  1. Open VS Code.
  2. Open the Extensions view (Cmd+Shift+X on macOS, Ctrl+Shift+X on Windows / Linux).
  3. Search for ESLint.
  4. Install the extension published by Microsoft — the one with millions of downloads.

Once installed, the ESLint extension reads your project's eslint.config.js and shows warnings and errors right in the editor. Warnings appear as yellow squiggles, errors as red. You can also see the full list in the Problems panel (View → Problems, or Cmd+Shift+M / Ctrl+Shift+M).

2. Install the Prettier extension

  1. Still in the Extensions view, search for Prettier - Code formatter.
  2. Install the extension published by Prettier.

The extension uses the version of Prettier installed in your project's node_modules. That means everyone on your team formats with the same version, regardless of which VS Code build they're running.

3. Set Prettier as the default formatter

  1. Open the Command Palette (Cmd+Shift+P / Ctrl+Shift+P).
  2. Run Preferences: Open User Settings (JSON).
  3. Add these entries to your user settings:
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true
}

editor.defaultFormatter tells VS Code which extension owns formatting. editor.formatOnSave tells VS Code to run that formatter every time you save. Together they mean Prettier will rewrite your file to the project's style on every Cmd+S / Ctrl+S.

4. Per-language overrides (optional)

If you only want Prettier for JavaScript and TypeScript but leave other languages alone, use per-language overrides instead:

{
  "editor.formatOnSave": true,
  "[javascript]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode"
  },
  "[typescript]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode"
  },
  "[json]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode"
  }
}

5. Workspace vs user settings

User settings apply to every VS Code window on your machine. Workspace settings apply only to the current project and can be committed to version control so every developer picks them up automatically.

To set workspace settings for a project, create .vscode/settings.json in the project root:

{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true
}

For a shared codebase, this is usually the better place to configure Prettier and ESLint — the settings ship with the repo, and every developer's editor behaves the same way.

6. Verify the setup

  1. Open any JavaScript file in your project.
  2. Intentionally break the formatting — remove a semicolon, mess up the indentation, squish operators together.
  3. Save the file. Prettier should format it back.
  4. Declare a variable but never use it. The ESLint extension should underline it in yellow and add an entry to the Problems panel.

If nothing happens on save, check three things: the extension is enabled (Extensions view → verify it does not have a "Disabled" label); editor.defaultFormatter is set to esbenp.prettier-vscode; and Prettier is installed in your project's node_modules (run npm install if needed).

Common gotchas

  • Multiple formatters compete. If another formatter is enabled (like the built-in JavaScript formatter, or a language-specific one you installed earlier), VS Code may prompt you to pick one every time. Setting editor.defaultFormatter explicitly resolves this.
  • Prettier and ESLint disagree on style. If you have style-related ESLint rules turned on that Prettier also handles, you'll see redundant warnings. Most projects use eslint-config-prettier to disable the overlapping rules. Check the Prettier docs for setup.
  • Format on save doesn't trigger. Format-on-save only runs on explicit saves. Auto-save with format-on-save can behave surprisingly — use Cmd+S / Ctrl+S if you want to see Prettier run.
  • The ESLint status bar item is red. Click it. It usually means ESLint failed to load — often because eslint.config.js has a syntax error, or a dependency is missing. The panel that opens shows the underlying error.
